## Como fechar corretamente um chamado de suporte

Fechar um chamado corretamente garante que o problema foi resolvido e deixa registro claro para futuras consultas. Este artigo explica o procedimento completo.

### Checklist de fechamento

#### 1. Verificação técnica

- [ ] Usuário testou solução
- [ ] Problema realmente resolvido
- [ ] Não houve efeito colateral
- [ ] Sistema está estável

#### 2. Comunicação com o usuário

- [ ] Explicou-se a solução
- [ ] Passos para evitar recorrência
- [ ] Quando abrir novo chamado
- [ ] Agradecimento pela paciência

#### 3. Registro no sistema

- [ ] Comentário final detalhado
- [ ] Solução aplicada (campo específico)
- [ ] Tempo de atendimento
- [ ] Categoria correta

### Modelo de comentário de fechamento

```markdown
Problema: [Descrição resumida]
Causa: [Raiz do problema identificada]
Solução: [O que foi feito para resolver]
Prevenção: [Como evitar recorrência]
Observação: [Informações adicionais]

O usuário testou a solução e confirmou a resolução completa.
```

### Regra do "20 minutos de follow-up"

Aguarde 20 minutos após fechar para:
- Verificar se o problema volta
- Confirmar satisfação do usuário
- Atualizar métricas se necessário

### Quando NÃO fechar o chamado

#### Situações de aguardo

- **Patch pendente** - Aguardar liberação
- **Manutenção programada** - Definir data de retomada
- **Aprovação gerencial** - Marcar como "Bloqueio"

#### Situações de escalonamento

- **Problema complexo** - Transferir para especialista
- **Bug conhecido** - Marcar como "Conhecido" + reabrir
- **Dependência externa** - Definir responsável

### Comunicação final

#### Mensagem padrão

```
Prezado [Nome],

O chamado #[número] foi encerrado com sucesso. A solução foi aplicada 
e testada em sua estação.

Caso o problema retorne ou tenha outra dúvida, por favor abra um 
novo chamado indicando este número para referência.

Agradecemos a sua colaboração.

Atenciosamente,
[Seu nome]
Suporte Técnico
```

### Métricas para fechamento

#### Qualidade do atendimento

- **Taxa de reabertura**: < 5%
- **Tempo de custódia real**: Dentro do SLA
- **Satisfação do usuário**: Conforme pesquisa

#### Documentação

- **Passos claros**: Usuário entende o que foi feito
- **Prevenção**: Aprendizado registrado
- **Link útil**: Artigo ou FAQ atualizado

### Erros comuns no fechamento

#### Prematuro

- **Problema**: Solução parcial aplicada
- **Consequência**: Reabertura do chamado
- **Correção**: Testar mais abrangermente

#### Sem comunicação

- **Problema**: Usuário não sabe que foi resolvido
- **Consequência**: Novo chamado por não acreditar
- **Correção**: Sempre confirmar com o usuário

#### Sem registro

- **Problema**: Não ficar registro da solução
- **Consequência**: Dificuldade de pesquisa futura
- **Correção**: Comentário detalhado obrigatório
